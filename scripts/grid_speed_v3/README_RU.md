# Эксперимент GridSpeed V3 — ускорение поиска печатной сетки

**Основа:** GitHub `ashybulakstroy/GridMesh_RapidOCR`, ветка `main`, проверенный коммит `c80b36cd9f5156f8394f6c26ae90b6e2655beb4a` от 23.11.2026.

**Только эксперимент!** Файлы `App/` не изменяются. Подмена функций `service.detect_for_lab` и `service.detect_physical_graph` осуществляется в памяти процесса на время одного теста с гарантированным восстановлением. Не подключайте этот модуль в рабочий веб-сервер: подмена не потокобезопасна.

## Задача

Разобраться, за счёт чего можно сократить поиск сетки, сохранив все физически наблюдаемые линии и строки. На примере настоящего профиля чека 51 040 ₸:

- AutoGrid GridRefine V3: **196,296 мс**, `found=false`;
- Physical Grid Graph V3: **510,598 мс**, `found=true`, `strong_short_grid`;
- общий поиск: **706,99 мс**; полная обработка: **1006,35 мс**.

Это измерение **одного** чека, а не гарантия времени для остальных. На другом чеке в интерфейсе видно 5,012 секунды поиска.

## Какие сценарии в гонке

| Код | Маршрут | Зачем |
|---|---|---|
| `baseline` | Текущий `App.geometry.service.build_grid` без изменений | Контроль времени и геометрии |
| `physical_only` | Сразу Physical Grid Graph V3, без AutoGrid | Проверить экономию неуспешного AutoGrid |
| `scaled_085` | Physical Grid Graph V3 на 85% изображения → масштабирование линий → проверка чернил **исходного** изображения → штатный Grid Mesh | Проверить более быстрый поиск без выдумывания строк |
| `scaled_070` | То же самое на 70% | Проверить границу качества/скорости |
| `autogrid_only` | Только AutoGrid; без дорогого fallback | Диагностика, какую долю фото AutoGrid решает самостоятельно; по умолчанию не включён |

`physical_only` не является безопасным универсальным производственным маршрутом. На фотографиях, где AutoGrid работает лучше, можно потерять сетку. Режимы 85% и 70% — **гипотезы**, проходят валидацию на исходных пикселях и могут быть отвергнуты.

## Как запустить в Windows 10

1. Распаковать ZIP, например в `D:\Benchmarks\GridSpeed_V3`.
2. Убедиться, что рабочий проект находится в `C:\Work\Projects\Prj_18_OCR_2`. Если проект находится в другом месте, изменить только `PROJECT_ROOT` в `.bat`.
3. Запустить **`run_quick.bat`** (6 реальных фото, по одному измерению) или **`run_full.bat`** (6 фото, 1 прогрев, 3 измерения каждого режима).
4. Открыть созданный `results\YYYYMMDD_HHMMSS\summary.html`. В этом же каталоге — `results.csv`, `results.json`, наложения `overlays/` и **копии оригинальных фото** `photos/`.

**Виртуальная среда:** берём интерпретатор и установленные `cv2`, `numpy`, `scipy` из `.venv` **основного** проекта. Ничего дополнительно не скачиваем и `.venv` не копируем. Это обеспечивает одинаковые версии вычислительных библиотек.

Если проект не в указанном каталоге:

```bat

run_quick.bat
```

Или через консоль:

```bat

  --project C:\Work\Projects\Prj_18_OCR_2 ^
```

### Фотографии

Эксперимент автоматически берёт **шесть настоящих изображений из текущего репозитория** (не скриншоты интерфейса):

- `App/tests/fixtures/receipt_short_51040.jpg`
- `App/tests/fixtures/receipt_253309.jpg`
- `App/tests/fixtures/receipt_29464.jpg`
- `App/tests/fixtures/receipt_32596.jpg`
- `App/tests/fixtures/receipt_fold_36981.jpg`
- `App/tests/fixtures/receipt_long_grid.png`

Исходные фотографии должны присутствовать в локальной копии проекта. **В ZIP бинарные оригиналы не вложены**: в данном сеансе их нельзя надёжно перенести из GitHub. При запуске эксперимент копирует их из локального проекта в папку результата, а в отчёте сохраняет SHA-256 каждого фото. Скрипт не загружает изображения из интернета и не использует нарезки с экрана браузера как подмену оригиналов.

Для конкретного чека с дверями на **261 464 ₸** используйте его исходное JPG/PNG, если оно есть на компьютере:

```bat
.venv\Scripts\python.exe D:\Benchmarks\GridSpeed_V3\grid_speed_experiment.py ^
  --project C:\Work\Projects\Prj_18_OCR_2 ^
  --images "D:\Receipts\two_doors_261464.jpg" --repeats 3
```

Для всех фотографий `receipt_*` из `App/tests` укажите `--all-fixtures`. Для произвольной папки: `--image-dir "D:\Receipts"`.

## Как проверяется качество

- Количество вертикальных и горизонтальных физических линий, количество полос строк.
- Координаты **всех пересечений** физической сетки; медианная ошибка ≤3 пикселей, максимальная ≤8 пикселей относительно `baseline`.
- Для уменьшенных фотографий все найденные горизонтальные линии дополнительно проверяются **на чернилах оригинального изображения** штатным `physical_grid_graph_v3.evidence`.
- Штатная `service.build_grid` по-прежнему выполняет `safety` и строит ячейки по исходным координатам.
- Для вручную размеченного чека можно прописать число полос в `truth.json`. Если это число не совпало, отметка качества `fail`.
- При отличающемся количестве линий результат считается `different_topology`, даже если средняя ошибка маленькая.

**Ограничение:** `baseline` тоже может ошибиться. Совпадение с ним не доказывает правильность! Итоговые кандидаты обязательно проверить по сохранённым изображениям; для чека с дверями ожидается **3 физических строки** (2 товара + НДС), для короткого чека 51 040 ₸ — **2** (товар + НДС). Напечатанный итог расположен **под** сеткой, OCR итога и НДС этот эксперимент не запускает.

Файл `truth.json` — минимальная разметка. Можно вписывать другие известные реальные чековые фото с ожидаемым `body_rows`.

## Правила приёмки

1. У нового маршрута нет пропущенных строк/столбцов ни на одном размеченном чеке.
2. Все линии подтверждены на исходном изображении и совпадают с проверенным эталоном или вручную приняты.
3. Замедления на сложных/изогнутых фото не превышают разумную цену, а выигрыш подтверждён повторными измерениями.
4. **Только после этого** обсуждается отдельный производственный патч с безопасным fallback и тестами. Нынешний пакет ничего в production не включает.

## Результат

`summary.html` — наглядные фото всех найденных сеток и сравнительная таблица; `results.csv` — одна строка на фото, ориентацию, маршрут и повтор; `results.json` — полный набор измерений, шаги детекторов, причины отклонения и контроль геометрии.

**Анализ скорости:** если `physical_only` стабильно выигрывает на коротких чеках, это не значит, что AutoGrid нужно удалить. Нужно разработать строго проверяемое правило переключения на таких фотографиях и сохранить полный маршрут в качестве fallback. Если уменьшенное изображение не прошло `original_pixel_ink_gate`, этот путь нельзя принимать независимо от скорости.

## Технические примечания

- Для альбомных фото проверяются оба поворота по 90°; выбор правильной ориентации по OCR заголовка в эксперимент **не включён**.
- Измеряется только геометрия, без прогрева OCR-моделей и без веб-интерфейса.
- Проверка исходных чернил для scaled-режимов — часть их измеренного времени.
- Время `time.process_time()` содержит CPU всех потоков процесса и не равно wall time.
- Не запускайте два эксперимента одновременно, если сравниваете CPU; для воспроизводимости выключите фоновые тяжёлые задачи.
- Если локальная версия репозитория отличается от зафиксированного SHA, программа показывает предупреждение. `--strict-sha` прекращает тестирование при несовпадении.
