# Original Numeric ROI + Candidate Matrix V4

**Экспериментальный патч для** `ashybulakstroy/GridMesh_RapidOCR` (ветка `main`, изучена 22.11.2026). Исходный репозиторий не изменяется. Код и реальный OCR на пользовательском компьютере необходимо проверить перед применением к рабочим счетам 1С.

## Главная цель V4

Получать максимально достоверные цифры **без перекладывания распознавания на пользователя**. Система самостоятельно исследует сомнительные числа; даже при неоднозначности пользователь не обязан выбирать «верную OCR-версию». Визуальное уведомление нейтральное, значения без достаточного подтверждения сохраняются без подмены. Это НЕ равнозначно статусу «все цифры доказанно верны»: в JSON остаются `review_required=true` и варианты.

### Что изменено относительно V3

1. **Маршрутизатор повторов:** при `OCR_E4_ROUTE_RETRIES=1` прежние первичный `p1_recovery`, пакетный `p1_double_retry` и дополнительный `recover_total_mismatch` не выполняют повторные чтения той же v5. Они замещаются проверкой исходных пикселей **другой моделью RapidOCR**. Это убирает часть избыточных REC, но не отключает начальное чтение всех ячеек и OCR печатного итога.
2. **Original Numeric ROI RAM:** исходное фото и замаскированные числовые вырезки остаются доступными без повторного GridMesh. При подозрении на ошибку `crop_numeric_ink()` работает непосредственно на исходных пикселях, не через `cv2.remap()`.
3. **Независимые распознаватели:** первая добавочная попытка — первая модель из `OCR_E2_NUMERIC_MODELS` (рекомендуется v6 Small). Если модель недоступна или не получила надёжное число, используется v5 на исходной вырезке. Вторая модель запускается только при неразрешённой математике либо для подтверждения предложенной исправляемой цифры. Второй этап ограничен `OCR_E4_SECOND_PASS_MAX`.
4. **Печатный итог и НДС:** отдельно читаются с фото, есть дополнительные OCR-варианты, confidence, метод и ID модели. Матрица сравнивает `сумма товаров + фактически напечатанный НДС = напечатанный итог`, а также `количество × цена` и независимые суммы строк, если они есть. **Расхождение НДС с 16% — только финансовая диагностика ошибки оператора**, а не доказательство ошибки OCR.
5. **Консервативная автокоррекция:** если существует ровно одна согласованная математическая комбинация без усечения поиска, предложенная замена подтверждена двумя *различными моделями*, печатный итог и НДС также имеют два модельных подтверждения (confidence ≥0.80), система сама исправляет соответствующее OCR-значение. Два прогона v5 на разных crop **не считаются** двумя независимыми моделями. Все исправления фиксируются в `numeric_auto_corrections`. При недостатке доказательств число не меняется.
6. **Пользовательские правки:** если пользователь самостоятельно меняет значение, оно становится `user_confirmed` после сохранения и имеет приоритет. Автоматика не вправе перезаписать `user_verified`.
7. **REC-трассировка:** `rec_trace` сохраняет модель, этап, успешность, миллисекунды и **число попаданий каждой ячейки в REC-only**, включая элементы батча. Отдельно считаются `DET+REC` вызовы: число внутренних REC, скрытых внутри детектора RapidOCR, не выдаётся за точно измеренное.

### Что НЕ делает эксперимент

- Не придумывает цифры исходя из суммы.
- Не считает арифметическое совпадение доказательством оптической правильности.
- Не заставляет пользователя разбирать неоднозначные значения.
- Не включает Tesseract.
- Не требует GPU; рассчитан на RapidOCR 3.10, ONNX Runtime CPU.
- Не загружает все модели в память заранее. При отсутствии локального кэша *официальная* модель RapidOCR **может скачаться при первом обращении**; внешние ONNX проверяются по файлу и SHA-256.

## Установка Windows 10

Сначала рекомендуется сохранить копию рабочего проекта. Если V1/V2/V3 уже применён **к этому проекту**, выполните откат именно тем установщиком/backup, которым его установили, и только после этого применяйте V4. Патч ориентирован на оригинальную структуру ветки `main`.

```bat
python install_experiment.py --project "C:\Work\Projects\Prj_18_OCR_2" --check
python install_experiment.py --project "C:\Work\Projects\Prj_18_OCR_2" --apply
python check_models.py --project "C:\Work\Projects\Prj_18_OCR_2"
```

Установщик по умолчанию выполняет только проверку, сохраняет резервные копии в:

`data/experiment_backups/OriginalROI_CandidateMatrix_V4/<timestamp>/`

Для отката:

```bat
python install_experiment.py --project "C:\Work\Projects\Prj_18_OCR_2" --rollback "C:\Work\Projects\Prj_18_OCR_2\data\experiment_backups\OriginalROI_CandidateMatrix_V4\<timestamp>"
```

Установщик **не переписывает `.env`**. Добавьте выбранные параметры из `env_models_example.txt` вручную, соблюдая существующие настройки. Если Python окружение переносилось из другой версии, убедитесь, что установлен именно `rapidocr==3.10.0`.

## Рекомендуемые `.env`-параметры

```ini
OCR_E2_ENABLE=1
OCR_E2_NUMERIC_MODELS=v6_small_official,v6_tiny_official
OCR_E2_FOOTER_MODELS=v6_small_official,v6_tiny_official
OCR_E2_VAT_MODELS=v6_small_official,v6_tiny_official
OCR_E2_MAX_MODEL_CALLS=16
OCR_E4_ROUTE_RETRIES=1
OCR_E4_SECOND_PASS=1
OCR_E4_SECOND_PASS_MAX=3
OCR_E4_AUTO_APPLY=1
OCR_E4_MIN_MODEL_AGREEMENT=2
OCR_ORIGINAL_CACHE_MB=32
OCR_ORIGINAL_MAX_RECOGNITIONS=8
OCR_FOOTER_VERIFY_ALWAYS=1
OCR_FOOTER_MAX_PROBES=8
OCR_VAT_VERIFY_ALWAYS=1
OCR_VAT_MAX_PROBES=6
OCR_MATRIX_MAX_NODES=100000
OCR_ONNX_THREADS=2
```

**Важно:** для целей сравнения задайте те же модели в контрольном режиме. С `OCR_E2_ENABLE=0` новые независимые чтения отсутствуют — остаётся резервная v5 на исходных пикселях и безопасное сохранение всех вариантов. `OCR_E4_ROUTE_RETRIES=0` возвращает старые повторные этапы v5, если нужно провести сравнительный бенчмарк. Если на первых реальных тестах обнаружатся ложные автоматические исправления, установите `OCR_E4_AUTO_APPLY=0`: анализ и альтернативы останутся, но числа в результате не будут изменяться.

## Что смотреть в JSON

`data/output/<job_id>/receipt.json` и `numeric_experiment.json`:

- `numeric_candidate_book`: все варианты по каждой цене/количеству/сумме строки, отдельно варианты итога и НДС;
- `numeric_matrix`: найденные решения, `status`, `critical_ambiguity`, `automatic_resolution`, `user_action_required=false`;
- `numeric_auto_corrections`: решения автоматики, модели и причины, почему замена разрешена/отклонена;
- `original_roi_experiment`: список оригинальных ROI, OCR-попытки, второй проход, время и ошибки;
- `rec_trace.per_cell`: вызовы REC по каждой ячейке; `rec_only_model_invocations` и `rec_only_cell_exposures` различают количество пакетных вызовов и количество обработанных картинок;
- `vat_rate_diagnostic`: расхождение с ожидаемой ставкой **не делает OCR ошибочным**;
- `numeric_user_truth.json` после сохранения: пользовательские значения и обратная связь о распознавателях.

В веб-форме отображается краткое состояние автоматической сверки; варианты остаются в подсказках и журнале. Сохранение чека не требует подтверждать каждый сомнительный вариант. Если матрица неоднозначна, **не объявлять чек проверенным** и не использовать математический статус как безусловное основание для автопроведения 1С.

## Интеграция в Проект 18 — 22.11.2026

Модули перенесены в App. В местной интеграции добавлены: распознавание напечатанного НДС в колонке количества при цене 1; единые идентификаторы голосов моделей; сброс REC-контекста через finally; сохранение ручных правок в памяти сервера между сохранениями. Часы REC-трассировки отделены от тестовых часов бюджета подготовки.

Включение всего маршрута: `OCR_E4_ENABLE=1`. Значение по умолчанию — `0`: используется прежний маршрут. Остальные OCR_E2/OCR_E4 параметры применяются при включённом маршруте. Локальные настройки потоков сохранены (на приёмочном сравнении intra_op=2, OpenCV=2).

Проверка девяти фото, в том числе шести с несовпадением итогов: 21 парный прогон до/V4. Ни одно выбранное числовое значение не изменилось, автокоррекций 0; все шесть исходных несовпадений сохранились. Сумма медиан времени по фото: 21.078 с до и 22.938 с V4 (+8.8%). Это ограниченная проверка, а не универсальная метрика качества. Поэтому маршрут V4 не активирован по умолчанию.

Приёмочные данные: `data/experiment_reports/OriginalROI_CandidateMatrix_V4/acceptance/`. Построение отчёта без запуска моделей: `python scripts/originalroi_v4/report_acceptance.py`. В JSON сохранены пути фото, идентификаторы заданий и сырые результаты.


## Уточнение правил V4 — 2026-11-22
Каждая модель поставляет кандидатов, без кворума моделей и порога confidence для математического выбора. Единственное решение полного поиска применяется автоматически, включая выбор итога и НДС из альтернатив. Несколько решений, обрезанный поиск и ручные блокировки запрещают автозамену. Отсутствующие цифры не вычисляются для добавления в кандидаты. Разные десятичные записи одного числа объединяются.

Уточнение: при нескольких решениях полного поиска автоматически выбирается комбинация с максимальной средней уверенностью выбранных чисел (лучшее наблюдение каждого числа, итог и прямой НДС включены). При равенстве оценок сохраняется порядок обхода; всегда показывается просьба проверить цифры. Поиск больше не останавливается на втором решении. Локально V4 включена.
