# GridMesh OCR — Number-only CnOCR V3 (read-only)

**Совместимость:** актуальная основная ветка `ashybulakstroy/GridMesh_RapidOCR` на коммите `a19598a3899e2da174ba94348885aa5e3474c493` (22.11.2026).

Эксперимент проверяет специализированную CnOCR `number-densenet_lite_136-fc` на уже сохранённых числовых ячейках после безопасного отделения T/Т/₸ через OpenCV. **Никаких изменений в `App/`, `.env`, `receipt.json` и рабочих результатах.**

## Что изменилось после V2

В актуальной ветке `collect_v5_candidates()` запускается **после прочтения итога**, но **в отдельной параллельной линии `footer` одновременно с таблицей** (для `OCR_TABLE_MODE=cell` и `OCR_E4_ENABLE=1`). Поэтому V3 показывает в разных колонках:

1. `gridmesh_initial`: первичный OCR (обычно PP-OCRv6 Tiny), `model` и исходное наблюдение;
2. `v5_numeric_candidate`: **независимый** PP-OCRv5, который не следует называть fallback, а также суммарное время его размеченных REC-вызовов из `rec_trace`;
3. Финальную цифру после повторов/E4;
4. CnOCR integer-only и время её вызова.

Кроме этого, отчёт отражает `geometry.ocr_batch.table_wall_ms`, `footer_lane_wall_ms`, `footer_wall_ms` и `v5_candidate_wall_ms`. **Эти времена перекрываются: их нельзя складывать для получения полной продолжительности чека.** В режиме `batch` параллельная линия может отсутствовать.

Если `OCR_E4_ENABLE=0` или часть кандидатов не собрана, отсутствующие наблюдения и времена будут `null`, без выдуманных значений. В полях количества/цены/суммы строки допускаются только целые числа; **напечатанный итог чека (`receipt.total`), где возможна дробная часть, исключён**. Ячейки с подозрением на дробную часть также пропускаются. Совпадение OCR-моделей не доказывает истинную правильность цифр — для оценки качества требуется эталон.

## Установка Windows

1. Распаковать ZIP **в корень** `GridMesh_RapidOCR`, должна появиться `experiments\numeric_only_crop_v3\`.
2. Запустить `experiments\numeric_only_crop_v3\install_cnocr.bat` (Python 3.12, независимое окружение от рабочего Python 3.14; окружение V2/V1 переиспользуется, если есть).
3. Обработать чек обычным приложением. Убедиться, что его папка содержит `receipt.json`, `original.png`, `rectification_map.npz`.
4. Запустить `experiments\numeric_only_crop_v3\run_latest.bat`. Будут 2 прогрева и 3 замера каждой ячейки (медиана).
5. Открыть `data\output\<job_id>\numeric_only_experiment_v3.html` и JSON с тем же именем.

Для проверки только OpenCV (без скачивания/загрузки CnOCR) запустить `run_preprocess_only.bat`. При `--save-crops` создаётся каталог `numeric_only_crops_v3/` с изображениями до и после обработки.

Для конкретного чека: 

```bat
experiments\numeric_only_crop_v3\run_latest.bat --job <job_id> --repeats 5 --save-crops
```

Модель CnOCR, работа с ней и скачивание весов **не тестировались на вашей Windows-машине**. Требуется интернет при первой загрузке весов и `cnocr[ort-cpu]==2.3.3` в изолированном окружении. При неудачной инициализации ошибка сохраняется в `numeric_only_experiment_v3.json`.

## Выход и оценка

- `numeric_only_experiment_v3.json`: полный аудит подготовки/распознавания, число, оценка уверенности, исходный PP-OCRv6 и параллельный кандидат PP-OCRv5, `rec_trace`, тайминги, ошибки, расхождения.
- `numeric_only_experiment_v3.html`: удобная таблица сравнения 4 значений.
- `numeric_only_crops_v3/`: только при `--save-crops`.

**Измерения:** отдельный Python-процесс CnOCR не работает одновременно с рабочими моделями. `production_debug_wall_ms` включает Python-обвязку, `rec_trace` отражает только инструментированные вызовы. Разницу в этих миллисекундах **нельзя объявлять доказанным ускорением**, это предварительная диагностика; для A/B нужны одинаковые изображения и повторные прогоны моделей в сопоставимых условиях.

## Тесты и откат

`experiments\numeric_only_crop_v3\test_experiment.bat` — запуск автономных тестов `unittest`, не требует весов CnOCR. При тестировании без полноценного проекта тесты используют stub только для `App.ocr.numeric_roi`; в настоящем проекте — его фактическую реализацию.

Откат: удалить папку `experiments\numeric_only_crop_v3` и созданные `numeric_only_experiment_v3.*` / `numeric_only_crops_v3` в конкретных папках чеков. Никакие оригинальные JSON и код не меняются.


## Приёмка в основном проекте

Отделение изолированного знака валюты с OCR-подсказкой добавлено как источник дополнительных вариантов цены для матрицы; исходные варианты сохраняются. Дробные цены и неотделимые знаки не обрезаются. На четырёх чеках финальные числовые значения до/после совпали; первоначальная проба с V6 давала ошибочный 3580 вместо 3560; в итоговой реализации дополнительный вариант читает отдельная V5, для этой ячейки получен 3560. Подтверждённого роста точности на этих чеках нет.

В режиме `original_cells` сохранённые map_x/map_y не являются картой OCR-вырезок: автоматический запуск runner теперь останавливается, чтобы исключить ошибочное сравнение. Для теста потребуется заново построить карту и проверить координаты каждой вырезки с результатом задания. Модель CnOCR и её бенчмарк отложены по запросу пользователя. В основном проекте RapidOCR 3.10.0 не менялся; CnOCR 2.3.3 с cnstd 1.2.8 в тестовом окружении несовместимы с текущим API RapidOCR 3.10.0.
