# OCR чеков — проект №18

Отдельное CPU-приложение для испытания геометрии и распознавания чеков. Проект не зависит от файлов, окружения и сервера проекта №17. Данные OCR и геометрия сохраняются в каталоге каждого задания.

## Запуск

Нужен 64-битный Python 3.14. Если окружение ещё не создано:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запустите `start.bat` и откройте `http://localhost:8018/`. Адрес, порт, потоки OpenCV и ONNX, ставка НДС и каталог результатов задаются в собственном `.env`. Перезапустите сервер после изменения настроек. При первом использовании модели RapidOCR скачиваются в окружение проекта; для этого нужен интернет.

Фото можно выбрать файлом или вставить в страницу из буфера обмена, после чего нажать «Распознать». Столбцы и суммы можно исправить. Кнопка «Сохранить JSON» записывает исправленный чек в каталог задания и скачивает копию. При ошибке сетки загрузите другое фото; приложение не подставляет вымышленные линии.

## Каталог задания

`data/output/<id>/`: `input.bin` (исходные байты), `original.png` (с учётом ориентации), `rectified.png` (таблица с сеткой), `rectification_map.npz` (обратная карта), `receipt.json`, `performance_profile.json`. После сохранения правок добавляется `receipt_edited.json`. При ошибке сохраняются `error.json` и профиль. Имя `rectified.png` сохраняется и для ровной таблицы, когда преобразование не потребовалось.

## Скорость и CPU

На странице во время выполнения показываются текущий этап, время и загрузка CPU; по окончании — журнал этапов. `process_cpu_ms` суммирует процессорное время потоков процесса, как в проекте №17. 100% CPU процесса соответствует одному занятому логическому ядру, поэтому возможно значение больше 100%; общий CPU показывается отдельно. Пики измеряются примерно раз в 0,2 секунды и могут пропустить короткие всплески. Для сравнения проектов используйте один и тот же оригинал и число потоков, несколько повторов после прогрева и одинаковые условия; CPU-время процесса может включать фоновую работу сервера. Распознаётся одно задание одновременно.

## Состав и ограничения

Геометрия: AutoGrid GridRefine V3 из `App/geometry/autogrid_gridrefine_v3`; резервный детектор — реальный `physical_grid_graph_v3.detect_physical_graph`; выпрямление — Grid Mesh из `geometry_lab/algorithms.py`. По умолчанию отображается исходная фотография с физической сеткой; для OCR каждая ячейка отдельно извлекается по обратной карте Grid Mesh с геометрическим выравниванием её изображения. Опция «Выпрямлять таблицу» дополнительно формирует и показывает целую выпрямленную таблицу. Сетка показывается до завершения OCR. Поддерживаются четырёхколоночные таблицы и другие структуры, если заголовки позволяют уверенно определить нужные столбцы.

OCR: `rapidocr` 3.10.0, детектор PP-OCRv5 mobile и распознаватель PP-OCRv5 Cyrillic mobile. Для распознанных латинских фрагментов дополнительно применяется English PP-OCRv5 mobile, если его оценка выше. Он не заменяет фрагмент, содержащий кириллицу. Публичная граница адаптера — `App/ocr/engine.py`: `read_full` и `read_cell`; если позже потребуется старая версия RapidOCR, заменять вызовы и преобразование результата следует внутри адаптера. Старая версия сейчас не установлена и автоматически не поддерживается. API сверено с [официальным исходным кодом RapidOCR 3.10.0](https://github.com/RapidAI/RapidOCR/blob/v3.10.0/python/rapidocr/main.py).

На повреждённых фото и на многостолбцовых чеках остаются ошибки символов и цифр; статус проверки и ручное исправление обязательны при предупреждении. На чеке с колёсами известна неточность сетки и OCR: приложение показывает предупреждение. Результаты нескольких тестов не доказывают, что проект №18 уже точнее или быстрее №17.

## Эксперимент OriginalROI Candidate Matrix V4

Включён локально через `OCR_E4_ENABLE=1`. Модели поставляют кандидатов без требования двух голосов. Полный поиск выбирает единственное арифметическое решение; при нескольких решениях выбирается максимальная средняя уверенность чисел с просьбой проверить цифры. Обрезанный поиск не даёт права на автозамену. На шести проблемных фото после изменения правил исправлены количество в чеке 93612 и итог 62060; четыре случая не решены. Отчёт: `data/experiment_reports/OriginalROI_CandidateMatrix_V4/unique_matrix/summary.json`.


## Поячеечный OCR таблицы

Основной режим `OCR_TABLE_MODE=cell`. Итог запускается первым в отдельном потоке с отдельными кешированными сессиями моделей и замком. Второй поток читает столбцы сверху вниз: наименования, количество, цена, сумма строки (если есть). Порядковый номер остаётся производным от физической сетки. Все числовые ROI готовятся заранее без ограничения времени; бюджеты подготовки в поячеечном режиме отключены по запросу пользователя. Распознавание остаётся индивидуальным, без пакета тензоров. Ошибка чтения ячейки включает существующий пакетный маршрут для этой ячейки; при ошибке всего маршрута таблица читается пакетно. Полный прежний режим доступен через `OCR_TABLE_MODE=batch`.

Если после чтения таблицы обнаружена строка НДС ниже сетки и граница итога изменилась, итог перечитывается по уточнённым координатам. Матрица V4 сохраняет независимые варианты и проверки. Разделение потоков само по себе не гарантирует правильность итогового числа.

Сравнение одного фото: `.\.venv\Scripts\python.exe scripts/compare_cell_batch.py --photo data/output/7a0d379e961547828dd608a2cbb74f4a/input.bin --repeats 5`. Оба режима прогреваются; пять парных повторов чередуются. Отчёт включает время OCR отдельно от геометрии, выбранные тексты и числа, совпадение сумм и статистику подготовки.


## DEBUG Performance V2

При `LOG_LEVEL=DEBUG` файл задания `performance_profile.json` содержит блок `debug`: применённые настройки, отдельные первичные ячейки и пакеты, потоки table/footer, геометрию, подготовку вырезок, вызовы моделей из существующего REC-trace и RAM по контрольным точкам. При INFO остаются стандартный профиль и краткие `issues`; подробная диагностика не собирается. Python-ошибки сохраняются и при неудачном завершении задания. Длительности потоков перекрываются и не складываются в общее время; RAM не является точным пиковым значением.

Исходный пакет и установщик: `scripts/gridmesh_debug_performance_v2/`. Резервная копия с манифестом: `data/experiments/gridmesh_debug_performance_v2/`. Локальная приёмка: `data/experiment_reports/gridmesh_debug_performance_v2/report.html`. На контрольном чеке 252161 выполнено по пять повторов до установки / INFO / DEBUG: все выбранные поля совпали. Медианы полного цикла около 2,15 / 2,15 / 2,14 с; разница укладывается в разброс измерений.


По умолчанию названия читает V6 Tiny Cyrillic, количества и цены — PP-OCRv6 Tiny; V5 применяется как резервная. Переключать модели через `.env` не требуется. При несовпадении суммы резервная V5 добавляет варианты чисел в матрицу. Tiny V6 — модель Metrika Labs из локального `models/ppocrv6_tiny_cyrillic/`, её SHA256 проверяется. При многострочном fallback с детектором остаётся V5. Сравнение на чеке da7ede65: `data/experiment_reports/name_models_da7ede65/report.html`; качество названий требует ручной сверки.


Для каждой числовой ячейки перед первым решением матрицы собираются отдельные варианты основной V6 Tiny и резервной V5; матрица также использует непосредственно прочитанный итог и НДС. Если полный поиск нашёл одну или несколько согласованных комбинаций, дополнительное чтение по оригинальным пикселям не запускается. При нескольких комбинациях выбирается наибольшая уверенность и требуется проверка. Если решение отсутствует, данных недостаточно или поиск обрезан лимитами, запускается резервный этап с оригинальными ROI, моделями и повторной матрицей. В `numeric_matrix.initial_status` и `fallback_used` сохранено, какой путь использован.

Чтение кандидатов V5 идёт в потоке итога после его распознавания, параллельно с таблицей; выбранные значения передаются матрице до решения. В профиле время OCR итога и чтения кандидатов указаны отдельно; время потоков перекрывается.


Для цены добавляется дополнительный OCR-вариант, если по OCR-подсказке и форме изображения можно уверенно отделить знак валюты. Дробные цены и неотделимые символы пропускаются. Дополнительный вариант распознаёт V5 в потоке итога; он участвует в матрице наряду с исходными V5/V6, без удаления первоначальных наблюдений. На четырёх тестовых чеках финальные значения не изменились; рост точности не подтверждён. CnOCR не интегрирован, его испытание отложено.
