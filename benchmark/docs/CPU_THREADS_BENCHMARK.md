# CPU Threads Benchmark — подготовка

Эксперимент выполнен 2026-11-21 с разрешения пользователя: 690 основных измерений, 45 контрольных измерений v5 batch и 52 повтора нестабильных замеров. Всего 787 сырых записей; в итоговой выборке 735 стабильных измерений. Результаты запусков хранятся локально и исключены из Git.

```powershell
.\.venv\Scripts\python.exe -m benchmark.core.cpu_threads plan
.\.venv\Scripts\python.exe -m benchmark.core.cpu_threads run --confirm-load
```

Результаты: `benchmark/data/output/cpu_threads_benchmark/report.html`, `results.json`, `results.csv`, `raw.jsonl` и журналы отдельных конфигураций. Существующий каталог результатов защищён от перезаписи.

Этап 1: intra_op 1,2,3,4,6,8; две кириллические модели, оба режима, три чека, пять повторов: 360 запусков. Этап 2: OpenCV 1,2,4 при победителе intra_op отдельно для модели и режима: 180 запусков. Этап 3: две прочие модели, baseline и объединение победителей этапа 1 для соответствующего режима: 60–180 запусков только числовых полей. Итого 600–720 измеряемых запусков. Прогрев и создание сессий отдельно.

`v5_cyrillic_mobile` и `v6_tiny_cyrillic_optional`: все названия со смешанной кириллицей и латиницей, количества, цены, НДС и итог. Остальные модели: `numeric_only`, без товарных названий. Точность числовой модели не считается успехом обработки всего чека.

В каждом процессе создаётся новая ONNX-сессия. Прочитываются `get_session_options()` и `get_providers()`, сверяются intra_op, inter_op=1, CPUExecutionProvider; OpenCV проверяется через `getNumThreads()`. Несовпадение → `NOT_APPLIED`. Сессии не выполняются параллельно. Фактические настройки записываются в каждый сырой результат.

Лёгкая проверка без OCR: реальные сессии локальной v6 Tiny Cyrillic вернули intra_op=2 и 3 соответственно, inter_op=1, OpenCV=2, CPUExecutionProvider, ORT_SEQUENTIAL. Модели не скачивались. В полном эксперименте сверка обязательна для каждой конфигурации.

Координаты должны уже существовать; при отсутствии эксперимент прекращается. GridMesh в эксперименте запрещён, даже на подготовке. Проверяется SHA256 подготовленных вырезок для каждого чека. Полное время включает чтение фото и вырезки по координатам; OCR loop исключает их. CPU-время OCR измеряется вокруг вызовов recognize_txt; 100% соответствует одному логическому ядру. RAM — выборочный пик всего процесса каждые 50 мс.

Порядок intra_op: 1,8,2,6,3,4; порядок моделей чередуется. Порядок чеков циклически меняется, режимы чередуются между повторами. Это уменьшает привязку к порядку, но не исключает температурные изменения. Перед измерением и во время него оценивается общая нагрузка CPU. Фоновая нагрузка >30% отмечается `UNSTABLE_BACKGROUND_CPU`; такие результаты сохраняются, но не допускаются к выбору победителя.

Победитель: минимальная сумма медиан OCR по чекам отдельно для модели и режима, только при наличии пяти стабильных повторов и без ухудшения каждого числового поля и проверенного текста относительно baseline. Если надёжного победителя нет, дальнейшие этапы останавливаются с сохранением отчёта.

Все 11 товарных названий трёх чеков сверены агентом; medium исправлен по увеличенному оригиналу. approved_by_user остаётся false. Учитываются CER названий, точные совпадения, производные суммы строк, арифметика итога и полный успех чека. Суммы строк вычисляются из распознанных количества и цены: на фото отдельной колонки сумм нет. Бенчмарк использует заданные ROI и не доказывает автоматическое обнаружение всех строк/итога на произвольной фотографии.


## Результат выполненного эксперимента

Для v5 Cyrillic и v6 Tiny Cyrillic на текущих трёх чеках рекомендованы intra_op=6, inter_op=1, OpenCV=2, batch=8 для обоих режимов. На этапе 1 v5 batch дала кандидата intra_op=8, но на этапе 2 появились большие выбросы времени. Дополнительный контроль 2 → 8 → 6 при OpenCV=2 подтвердил более устойчивый вариант intra_op=6. Температура CPU не измерялась, причина выбросов не установлена.

Текстовые и числовые результаты разделены. Все названия оценены по проверенной агентом разметке; в названиях остаются ошибки. v5 распознала числовые поля этих трёх чеков без ошибок; это не гарантирует точность на произвольных чеках. Во время этапа 1 порядок конфигураций изменён по указанию пользователя на чередование отдельных лёгких/тяжёлых сессий, завершённые измерения сохранены.
