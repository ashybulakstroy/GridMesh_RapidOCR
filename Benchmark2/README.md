# Benchmark2 — кириллический OCR для чеков Торгсофт

Независимая гонка **шести** CPU OCR-движков в Windows 10, Python **3.14**, Intel i5-13400.
Запуск не трогает рабочие файлы или `.venv` основного проекта.

Подробная документация: задача, план, модели, решения и журнал прогресса — в
[`docs/README.md`](docs/README.md).

## 0. Запуск с другого диска — рекомендуемый вариант

**Местоположение папки Benchmark2 не привязано к диску C:** можно распаковать ZIP,
например, как `D:\OCR_Benchmark2\Benchmark2\` или `E:\Tests\Benchmark2\`.
Внутри распакованной папки запустить **`INSTALL_AND_RUN.bat`** двойным кликом.

Подтверждённый путь основного проекта остаётся **`C:\Work\Projects\Prj_18_OCR_2`**.
Новая `.venv`, вырезки изображений, скачанные модели и результаты будут храниться
**только внутри распакованной папки Benchmark2** на выбранном диске.

Пути Benchmark2 вычисляются по местоположению `.bat` (`%~dp0`) и
`__file__` модулей Python; нельзя менять расположение самого проекта после
создания `.venv` без её пересоздания. Если перенесли уже установленную папку,
удалите **только `Benchmark2\.venv`** и повторно запустите `INSTALL_AND_RUN.bat`.
Основной проект и его `.venv` при этом не затрагиваются.

Скрипт создаёт новое окружение Python на выбранном диске и восстанавливает
`pip freeze` оригинальной `.venv`. Физически копировать Windows `.venv`
между дисками небезопасно из-за встроенных абсолютных путей. Если интернет
недоступен, автоматическая загрузка пакетов/моделей может не выполниться.

## 1. Входные данные

**17 неизменённых ROI в исходных размерах**, размеченных в публичном репозитории
`ashybulakstroy/GridMesh_RapidOCR`:

- 11 названий товара (1+2+8);
- 3 строки «НДС 16 %»;
- 3 поля «Итого».

Оригинальные фото: `1000696512.jpg`, `1000697084.jpg`, `receipt_2142830502.jpg`.
Сверяются исходные **SHA256** (не только имена файлов). На этапе `prepare`
выделяются ячейки по архивным координатам `bbox`; изменение масштаба запрещено.
Длинные названия могут разбиваться на строки **одинаковым** алгоритмом для каждой модели,
после OCR обратно объединяются. Исходные PNG/координаты не меняются.

**Важно:** ZIP не содержит сами JPEG и ONNX-веса; подготовка берёт исходные фото
с диска основного проекта, либо скачивает опубликованные исходные JPG. На первой
подготовке нужен интернет, если файлов нет на ПК. Ячейки будут созданы реально,
а не подменены синтетическими изображениями.

Эталонные тексты — предварительно проверенные по оригиналу (не утверждены владельцем).
Показатели точности предварительные; код не корректирует ответы по математике или словарю.

## 2. Установка на целевом ПК

Распакуйте каталог `Benchmark2` на удобный диск, например
`D:\OCR_Benchmark2\Benchmark2` или `E:\Tests\Benchmark2`.
Запустите `setup_benchmark2.bat`. Скрипт:

1. Проверяет основной `C:\Work\Projects\Prj_18_OCR_2\.venv` (Python 3.14).
2. Создаёт отдельный `Benchmark2\.venv` (не копирует бинарный venv, потому что
   Windows `.venv` содержит абсолютные пути).
3. Экспортирует `pip freeze` основного проекта и восстанавливает установленные
   пакеты в новом окружении.
4. Устанавливает RapidOCR, Tesseract Fast, PyWinRT, psutil и модельный загрузчик.
5. Проверяет `pip check` и структуру бенчмарка.

Полный вывод установки, включая `pip`, автоматически пишется в
`Benchmark2\logs\setup_<дата>_<время>.log`. Успешный лог заканчивается строкой
`[BENCHMARK2] Setup exit code: 0`. При ошибке установщик возвращает ненулевой код,
а лог остаётся для диагностики. Каталог `logs\` не попадает в git (кроме `.gitkeep`).

Это **воссоздание из зафиксированного списка версий**, а не рискованное копирование
папки `.venv`. Основное окружение не изменяется. Если установка snapshot
конфликтует, исправить пакетные зависимости **только в клоне**.

Путь источника по умолчанию подтверждён: `C:\Work\Projects\Prj_18_OCR_2`.
При необходимости другой исходный проект можно задать переменной окружения
`BENCHMARK2_BASE_PROJECT` или параметром `-BaseProject` для `scripts/setup.ps1`.

## 3. Запуск

Двойной клик по `run_benchmark2.bat`.

Или в PowerShell:

```powershell
cd D:\OCR_Benchmark2\Benchmark2
.\.venv\Scripts\python.exe -m benchmark2 validate
.\.venv\Scripts\python.exe -m benchmark2 prepare
.\.venv\Scripts\python.exe -m benchmark2 models
.\.venv\Scripts\python.exe -m benchmark2 run
```

При запуске открывается **локальный HTML-дэшборд** в браузере:
`http://127.0.0.1:18018/`. Порт можно переопределить переменной окружения
`BENCHMARK2_PORT`; если 18018 занят, запуск остановится с понятной ошибкой.
Показывает модель, ячейку, процент готовности, прошедшее время, оценку
оставшегося времени, загрузку CPU всего и CPU процесса, последние миллисекунды.
При завершении выводит итоговый HTML-отчёт. Для закрытия локального сервера
нажмите Enter в консоли.

## 4. Протокол

Модели: `PP-OCRv3 Cyrillic Mobile`, `PP-OCRv5 Cyrillic Mobile`, `PP-OCRv6
Tiny Cyrillic`, `PP-OCRv6 Medium Cyrillic`, `Tesseract Fast Russian+English`,
`Windows OCR Russian`.

Всего 6 × 17 × 3 = **306 операций по физическим ячейкам**.
Проход №1 — прогрев, №2 и №3 — измеряемые. Если одно название состоит из двух
строк, время обеих входит в один замер физической ячейки.

Никакого намеренного тюнинга потоков, входных масштабов, батчей, словарей или
скорости нет. Обязательные параметры: выбор весов и языка, выключение детектора
для уже вырезанной ячейки, архитектурное `[3,48,640]` для внешней модели,
`PSM.SINGLE_LINE` для Tesseract (для однострочного сегмента).

Для v6 Tiny сначала берётся проверенная по SHA256 модель основного проекта;
при её отсутствии используется Hugging Face. Medium загружается из
`metrika-labs/PP-OCRv6_medium_rec_cyrillic_onnx`, SHA256 записывается в журнал.
Официальные RapidOCR модели используют штатную загрузку/кеш. Windows OCR
требует установленный русский языковой пакет OCR Windows 10. Библиотечные и
языковые ошибки записываются отдельно, без подмены другой моделью.

## 5. Результаты

В `results/<дата_и_время>/` сохраняются:

- `report.html` — таблица по моделям, сравнение абсолютного времени 17 ячеек,
  медиана времени имени, CPU, CER, распознанные тексты и фотографии вырезок;
- `raw.jsonl` и `raw.csv` — все 306 попыток (включая прогрев), время, текст,
  confidence (если доступно), ошибки, потребление CPU/RAM;
- `summary.json` — агрегаты;
- `status.json` — статус/процент/ETA;
- `inputs.json` — 17 исходных ячеек, размеры, координаты и SHA256;
- `environment.json` — версии библиотек/OS/Python;
- `model_initialization.json` — время загрузки/состояние/контрольные суммы;
- `manifest.json` — параметры протокола.

Ошибки не скрываются; участник, не готовый к исполнению, помечается
UNAVAILABLE и не может стать победителем.

## 6. Ограничения

Результаты на i5-13400 пока отсутствуют: настоящий тест необходимо запустить
на целевом ПК. Сразу после распаковки нет чисел в миллисекундах; никаких
вымышленных метрик в отчёте нет.

«Оригинальный размер ROI» относится к исходным фото, не к уже выпрямленной
таблице GridMesh: в режиме отдельного распознавания ячеек геометрия не вызывается.

**Один клик с любого диска:** `INSTALL_AND_RUN.bat` — установит отдельную среду при её отсутствии,
затем выполнит импорт настоящих JPEG/весов и запустит тест с HTML-прогрессом.
