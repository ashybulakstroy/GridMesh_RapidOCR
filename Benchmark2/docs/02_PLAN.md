# 02. План работ

## 2.1 Принцип

Работа разбита на этапы. Этап считается завершённым только после фактической проверки,
а не после написания кода. Статусы:

- **DONE** — выполнено и проверено, есть воспроизводимое свидетельство;
- **PARTIAL** — выполнено частично, есть явное ограничение;
- **PENDING** — не начато;
- **BLOCKED** — требуется решение владельца.

## 2.3 Этап 8 — политика Windows OCR

Windows OCR возвращает пустую строку на части коротких однострочных ROI высотой 28–38 px.
Добавление белой рамки 10 px делает строку «НДС 16 %» читаемой, но это меняет входные
данные и требует одинакового правила для всех моделей либо явной оговорки только для
Windows OCR.

Варианты для решения владельца:

1. **Строго оригинальные ROI для всех** — Windows OCR честно получает пустые ответы
   на части ячеек; это его реальное поведение в текущем протоколе.
2. **Белая рамка 10 px для всех моделей** — протокол меняется для всех одинаково;
   требуется пересоздание входов и повторная проверка.
3. **Отдельный протокол для Windows OCR** — результаты помечаются как несравнимые
   с остальными; в отчёте обязательна сноска.
4. **Исключить Windows OCR** — если поведение на целевых ROI считается неприемлемым.

Текущее состояние: **никакого padding нет**, входы оригинальные. Молчаливое добавление
рамки запрещено.

## 2.4 Этап 9 — порядок полного прогона

Предварительные условия:

1. Нет фоновых тяжёлых задач; питание ноутбука/ПК от сети.
2. Свободен порт `18018` (или задан другой `BENCHMARK2_PORT`).
3. `.venv` установлен и прошёл `validate`.
4. `data\cells\` содержит 17 PNG; `models_manifest.json` — READY для внешних моделей.
5. Принято решение по этапу 8.

Команда:

```powershell
cd C:\Work\Projects\Prj_18_OCR_2\Benchmark2
.\.venv\Scripts\python.exe -m benchmark2 validate
.\run_benchmark2.bat
```

`run_benchmark2.bat`:

- проверяет `.venv` и маркер пути;
- выставляет `BENCHMARK2_PORT=18018`, если переменная не задана;
- запускает `python -m benchmark2 run`;
- открывает локальный дэшборд `http://127.0.0.1:18018/`.

Во время прогона нельзя менять состав моделей, ROI, масштаб или параметры потоков.

## 2.6 Этап 11 — утверждение эталонов

Эталонные тексты в `data/samples.json` проверены по оригиналам, но не утверждены владельцем.
До утверждения все CER/точность в отчёте должны называться **предварительными**.
Если владелец исправит эталон, потребуется повторный прогон или пересчёт метрик
по сохранённым `raw.jsonl` (сырые ответы не теряются).
