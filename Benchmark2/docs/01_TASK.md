# 01. Задача

## 1.1 Цель

Подготовить и выполнить **независимый воспроизводимый бенчмарк** шести CPU-движков
распознавания текста (OCR) на реальных кириллических ROI чеков Торгсофт — без изменения
рабочего проекта `C:\Work\Projects\Prj_18_OCR_2` и без использования чужих замеров.

Бенчмарк должен позволить владельцу проекта сравнить скорость и качество распознавания
на одинаковых исходных изображениях и одинаковом протоколе, а затем принять решение
о выборе движка для основного приложения.

## 1.2 Что именно измеряется

- **17 физических ячеек** из трёх реальных JPEG-фотографий чеков.
- **6 OCR-движков** (только кириллица).
- **3 прохода** по каждой комбинации «модель × ячейка»:
  - проход 1 — прогрев, в итоговые метрики не входит;
  - проходы 2 и 3 — измеряемые.
- Итого: `6 × 17 × 3 = 306` операций распознавания.

Для каждого измерения фиксируются: время, распознанный текст, confidence (если движок
его отдаёт), ошибка (если возникла), загрузка CPU процесса и системы, потребление RAM.
Метрики качества: CER и расстояние Левенштейна к предварительному эталону.
Никакой нормализации, «исправляющей» ответы по словарю или математике чека, нет.

## 1.5 Требования и ограничения

| № | Требование | Как выполнено |
|---|---|---|
| R1 | Не изменять родительский проект и его `.venv` | Все записи только внутри `Benchmark2`; родительский `.venv` читается для `pip freeze` и копирования моделей |
| R2 | Отдельное окружение Python 3.14 | Создан `Benchmark2\.venv`, Python 3.14.2 |
| R3 | Новые OCR-библиотеки — только в клон | RapidOCR, tesserocr, WinRT, psutil, huggingface-hub установлены только в `Benchmark2\.venv` |
| R4 | Сначала проверить, какие модели уже есть | Инвентаризация родительского проекта выполнена до скачивания; результаты в [04_MODELS.md](04_MODELS.md) |
| R5 | Не подменять реальные данные синтетикой | 17 ROI нарезаны из трёх реальных JPEG, SHA256 сверены |
| R6 | Не масштабировать ROI | Размеры вырезок равны пиксельным bbox исходников |
| R7 | Фиксированный порт дэшборда | `127.0.0.1:18018`, переопределение `BENCHMARK2_PORT`; занятый порт — понятная ошибка, без случайного fallback |
| R8 | Полные setup-логи | Пишутся в `Benchmark2\logs\setup_<timestamp>.log`, включая вывод `pip` |
| R9 | Не выдумывать измерения | Полный прогон ещё не выполнен; в документации нет «оценочных» миллисекунд |
| R10 | Портативность | Пути вычисляются от расположения `.bat` и `__file__`; `.venv` при переносе пересоздаётся |

## 1.6 Критерии готовности

Подготовка считается завершённой, когда:

- [x] Создан отдельный `Benchmark2\.venv` на Python 3.14.
- [x] `pip check` не находит конфликтов.
- [x] `python -m benchmark2 validate` подтверждает 17 ROI и 6 движков.
- [x] Все 17 ROI созданы и имеют SHA256 в манифесте.
- [x] Модели v6 Tiny/Medium и веса RapidOCR доступны, хэши проверены.
- [x] Русский язык Tesseract и Windows OCR доступен.
- [x] Все шесть адаптеров загружаются и выполняют пробное распознавание.
- [x] Setup-логи пишутся в `Benchmark2\logs\`.
- [ ] Принято решение по политике Windows OCR для узких строк.
- [ ] Выполнен полный прогон 306 операций.
- [ ] Проверены `raw.jsonl`/`raw.csv` (306 строк), отчёт и отсутствие подмены ошибок.
- [ ] Эталонные тексты утверждены владельцем либо явно оставлены предварительными.

## 1.7 Что НЕ входит в задачу

- Обучение или дообучение моделей.
- Сравнение GPU-движков, облачных OCR-API и чужих бенчмарков.
- Детекция текста на полном изображении: распознаются уже вырезанные ROI.
- Автоматическое исправление ответов OCR по словарю, валюте или арифметике чека.
- Изменение бизнес-логики основного приложения `Prj_18_OCR_2`.
